1.
Hospitals deal with large amounts of information every day, including patient records, appointments, staff details and medical information. Managing all this information can become difficult, particularly when different departments use separate systems. This can lead to mistakes and difficulties accessing the information needed to provide effective patient care. The aim of this project is to develop a Hospital Management System that helps improve how these activities are managed. The system will allow hospital staff, including doctors, nurses and administrative workers, to manage patient information, appointments and other important hospital services in one organised system. The Hospital Management System will consist of several independent services, each responsible for a specific function, such as patient management, appointment scheduling and billing. Each service will be able to operate and be updated independently, making the overall system easier to maintain. This will follow a microservices architecture. Object-Oriented Programming (OOP) will be the chosen programming paradigm because it allows the system to be organised using classes and objects that represent real-world entities, such as patients, doctors and appointments. Concepts such as encapsulation, inheritance and abstraction will help keep the code organised and reusable. Combining OOP with microservices will provide a structured foundation for a system that can be maintained and expanded as hospital requirements change.

2.1
Object-Oriented Programming (OOP) was selected for the Hospital Management System because the system involves different users and activities that can be represented as objects. For example, patients, doctors, nurses and appointments all have different information and responsibilities within the system. Using OOP makes it possible to organise these into separate classes, rather than having all the information and functions mixed together. One way this would be used is through encapsulation. A Patient class could store information such as the patient's name, date of birth and contact details. Instead of allowing this information to be changed directly, methods could be used to control how it is accessed and updated. This is particularly important in a hospital system, where patient information needs to be handled carefully. Inheritance could also be useful when creating different types of hospital staff. For example, doctors and nurses share some information, such as their names, employee IDs and contact details. Rather than writing these details separately for each type of staff member, they could be stored in a general Staff class. The Doctor and Nurse classes could then inherit this information while having their own additional features. Polymorphism would allow different types of staff to use similar functions in different ways. For example, doctors and nurses may both need to access patient records, but they may have different responsibilities when updating or managing them. Abstraction would also help simplify the system by hiding unnecessary details. A member of staff booking an appointment, for instance, would only need to enter the relevant patient and appointment details without needing to know how the information is processed in the background. These examples show how OOP can be applied to different parts of the Hospital Management System. It provides a way to organise the information and functions needed by each part of the application, making the overall development process easier to manage. OOP is a suitable choice for this project because of the amount of information the Hospital Management System needs to handle. Patients, staff and appointments all have their own details, but they are also connected to one another. Organising them into classes makes these relationships easier to manage and helps keep the code structured. Another reason for choosing OOP is that it can save time when developing new features. For example, if another type of hospital staff needs to be added, an existing Staff class could be reused instead of creating everything from the beginning. This would be useful if the hospital decides to introduce additional departments or expand the system in the future. There are also some disadvantages to consider. As more classes are added, the relationships between them can become complicated. If the classes are not planned properly, making changes to one part of the system could affect other parts. This means the code needs to be organised carefully, with each class having a clear responsibility. Overall, OOP is a good fit for the Hospital Management System because it allows the different parts of the system to be organised around the people and activities involved in hospital management. It also makes the code easier to reuse and update, which will be important as the system develops.
